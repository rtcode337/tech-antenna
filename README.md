# tech-antenna

技術情報を自動で収集し、**記事・ニュース・論文・イベント・書籍**を1つの導線にまとめて届けるWebアプリ。

> 「今このトピックが伸びている → 関連する勉強会が近くである → 深掘りするならこの本・この論文」

## 状態

**開発初期。** 記事・ニュース・論文・イベント・書籍の収集と一覧表示、タグによる横断、
PostgreSQL への保存、タグからのトピック一覧生成、LLM による要約と論文タイトルの和訳まで実装済み。

## 構成

| 領域 | 採用 |
|---|---|
| ランタイム | .NET 10 (LTS) |
| Web | ASP.NET Core + Blazor |
| 収集ジョブ | `BackgroundService` |
| DB | PostgreSQL + EF Core |
| 要約 | Claude Code ヘッドレス(`claude -p`)/ Anthropic API |

## データソース

- **記事** — Qiita・Zenn・はてなブックマーク テクノロジー等の RSS / Atom
- **ニュース** — Publickey・ITmedia NEWS・InfoQ Japan・CodeZine の RSS
- **論文** — arXiv(英語。タイトルは LLM で和訳)/ J-STAGE(日本語)
- **書籍** — Google Books API(検索)/ openBD(書誌)/ 楽天ブックス(レビュー)/
  Qiita(「読むべき技術書」を挙げた記事から薦められている本)
- **イベント** — connpass API(API キーが必要)/ Doorkeeper API(アクセストークンが必要)/
  TECH PLAY の RSS

どこにキーが要るのか、設定できているのかは画面の**「設定 → 外部連携」**(`/integrations`)で
用途ごとに一覧できる(**キーの値そのものは表示しない**。有無だけを見る)。

## トピックの再編成

一覧は画面の**「設定 → トピック」**(`/topics`)。**新規トピックの候補は記事・イベント・書籍の
収集で自然に溜まる**(集めたデータのタグから見つける。候補はこのページの「新規トピック候補」で
見える)。**「トピックを再編成」**を押すと、候補を LLM で分類してツリーへ組み込みつつ、
語彙・話題度・タグの件数を突き合わせてトピック一覧を作り直す。

- 一覧の左のチェックボックスが**収集対象の選択**。「選択を保存」で確定する。イベント・書籍は
  選んだトピックを検索語にして問い合わせるので、**何も選んでいないと 1 件も集まらない**
- **親を選ぶと配下のトピックもまとめて収集対象になる**(保存のときに広げる)。子だけを外すことは
  できないので、外したいときは親のチェックを外して選び直す。イベントと書籍はトピック 1 つごとに
  外部へ問い合わせるため、**大きな親を選ぶとリクエスト数も配下のぶんだけ増える**
- **記事だけは選択で絞らない。** RSS は検索ではなく巡回なので、絞っても収集先への負荷は
  変わらず、捨てると「選んだトピックの外で何が起きているか」が見えなくなる。
  流れてきた記事はすべて保存し、選んだトピックのものを**一覧で強調する**(太字・左の帯・
  タグの色)。選択が空でも記事は集まる
- **選択したトピックは一覧の先頭に固定する。** 再収集でそのトピックが見つからなくなっても
  一覧からは消えない(話題度が 0 になるだけ)。押し出されて画面から消えると、選択の保存は
  一覧に出ている分で置き換えるため、選択そのものが外れて収集が止まってしまう
- 話題度の材料は **Qiita の新着記事(いいね数)** と **はてなブックマークの人気エントリー
  (ブックマーク数)**。どちらも収集ボタンを押した時点でその場から取得し、記事の収集状況には
  依存しない。**材料ごとのシェアに直してから合算する** —— 桁の違う値をそのまま足すと、
  桁の大きい材料が常に勝ってしまうため。算出方法は画面(設定 → トピック)の折りたたみにも書いてある
- **カタログに無い語は LLM が分類してツリーへ入れる**(要約と同じ方式・同じ設定。未設定なら
  分類なしで動く)。既存トピックの同義語なら寄せ、粒度が違う語なら親付きの新トピックにする。
  「トピックでない」と確定した語(ニュース・開発 のような一般語)は**一覧から取り除く**
  (記事などのタグとしては残る)。一覧は**親子のツリー順**で、子は親の下に1段下がる。
  分類を人手で直したいときは `topic-catalog.json` に書く(同じ語は JSON が勝つ)
- **集めた記事・イベント・書籍の件数は順位に足さない。** 集めるのは選択したトピックだけなので、
  件数で加点すると選択済みが上位に張り付き、新しいトピックが浮上しなくなる
- **トピック名を押すと詳細**(`/topics/<タグ>`)。その語の**一言説明**と**同義語**
  (どの表記を寄せているか。LLM が分類した分は印を付ける)と**親子ツリー上の位置**、
  続けて紐づいた記事・イベント・書籍が出る
- **一覧はツリー表示なら全件**(話題度 0 のトピックも消えない)、ランキング表示は上位 150 件。
  行にはトピック名と**その語がタグに付いた記事の件数**が並ぶ
- **見慣れない用語には一言説明が付く**(PC はトピック名の後ろのかっこ書き、
  スマホは `?` を押すとチップで出る)。新しく見つかった語の
  説明は**分類の応答に相乗り**していて追加の呼び出しは無く、以前からある語は再編成のたびに
  300 語まで埋める(**1 語につき 1 回だけ**聞いて保存する)。`topic-catalog.json` に
  `description` を書けば、そちらが優先される
- ホームのトピック欄には、この一覧の上位 10 件(選択済み → 話題度順)が並ぶ
- 話題度**だけ**が再編成のたびに外部から取り直される(候補集めは外部に依存しない)

## 記事・ニュース・論文

「直近動向」画面(親)の**「記事の収集」**で、RSS のフィードと論文の API をまとめて
1 巡する。直近動向は**興味のあるトピックに限らず**直近 7 日の話題をニュース→記事の順に
新着で数件ずつ一望する場所で、種別ごとの全量は子ページ(ニュース / 記事 / 論文)が
**新着順**で受け持つ。

- **話題度(はてなブックマーク数)は目立ち方に出す**。バッジが件数で 3 段階に変わり、
  直近動向ではカードの面にも同じ段階が出る。並び順は新着のまま —— 人気順に並べ替えると
  「今日なにが出たか」を追えなくなる。件数は収集のたびに、はてブの件数 API(キー不要)で
  直近分をまとめて引き直す
- **興味のあるトピックに当たる記事はタイトルの前に黄色い★**が付く(トピックは設定で選ぶ)

- **記事とニュースの違いは設定の `Kind` だけ**(`Collection:Feeds` の各フィードに書く)。
  保存先もタグの扱いも同じで、画面で出所が混ざらないようにするための区別
- **タグはフィードのカテゴリ + タイトルから見つけたトピック**。Zenn の RSS も Qiita の Atom も
  `category` を持たないため、収集元のタグだけに頼ると 7 割方タグ無しになり、トピック横断にも
  一覧の強調にも乗らない。誤爆を避けるため判定は `KeywordMatcher`(`AI` は `Rails`・`email` に
  当たらない)で、見るのは**タイトルだけ**(本文まで見ると一度触れただけの語で付いてしまう)
- **論文は arXiv(英語)と J-STAGE(日本語)**。どちらもキー不要で、選択中のトピックを検索語に
  1 つずつ問い合わせる。arXiv には**カタログの英語別名**を投げる —— 日本語のままだと 0 件になる
  (実測で `生成AI` は 0 件)。取り込むのはタイトル・URL・投稿日だけで、abstract は取り込まない
- **英語論文のタイトルは「論文タイトルの翻訳」ボタンで和訳できる**(要約と同じ LLM の枠)。
  訳題を見出しにし、**原題は下に小さく残す** —— 消すと他の文献と突き合わせられなくなる。
  日本語のタイトルは訳さないものとして確定するので、J-STAGE の論文は LLM を消費しない

## 書籍収集

「書籍」画面の**「書籍の収集」**で、選択中のトピック 1 つずつで Google Books を検索し、
openBD で書誌情報を補ってから保存する。**検索語は設定ではなくトピックの選択**から来る
(→[トピックの再編成](#トピックの再編成))。

集めたいのは新刊ではなく**その分野で読んでおくべき本**なので、検索は関連度順で引き、
並びはレビューの多さ(=どのくらい読まれているか)で決める。

- **検索は Google Books、補完は openBD(書誌)と楽天ブックス(レビュー)** と役割を分けている。
  openBD は日本の書誌を無料で引けるが**キーワード検索を持たず ISBN 参照専用**なので、
  検索で得た ISBN で引き直して**欠けている項目だけ**を埋める(既に値がある項目は上書きしない)
- **読まれている度合いは楽天ブックスのレビュー件数と平均評価**。評価をベイズ平均で件数に応じて
  割り引き、件数の対数を掛けて並べる —— 件数だけだと評価の低い話題書が定番書を押しのけ、
  評価だけだとレビュー 1 件で星 5 の本が最上位に来るため。ISBN の一括指定ができない API なので
  1 冊ずつ 1 秒空けて引く。**レビューを画面に出すときは楽天ウェブサービスのクレジット表記が必要**
  (アプリ ID は `RAKUTEN_APPLICATION_ID`。未設定ならレビュー無しで動く)
- Google Books の `ratingsCount` は日本語書籍にほぼ入っていない(実測 20 件中 0 件)ため使わない
- **Google Books の API キーは実質必須。** キー無しのリクエストは Google 共有の匿名プロジェクトの
  枠に入り、その枠は 1 日あたり 0 件なので最初の 1 回から 429 になる(`Books__GoogleBooksApiKey`)
- 検索条件は `langRestrict=ja`(日本語の技術書を拾うため)だけで、**並びは既定の関連度順**。
  1 キーワードにつき 20 件、キーワードの間は 2 秒空ける。`orderBy=newest` を使わないのは、
  新刊が欲しいわけではないうえに取りこぼしが大きいため(実測で `機械学習` は新着順だと 0 件、
  関連度順なら 300 件)
- 取り込むのは**書誌事実だけ**(タイトル・著者・出版社・刊行日・ISBN・リンク・書影 URL)。
  `description` などの出版社の著作物は取り込まず、書影も画像は持たず URL のリンクにとどめる
- 同じ本かどうかは **ISBN-13 →(無ければ)詳細ページの URL →(無ければ)タイトル**で判定する。
  既にある本は書誌情報を上書きしないが、**タグだけは足す** —— 1 冊が `AI` でも `LLM` でも
  見つかることがあり、捨てると最初のトピックにしか出てこないため
- **「読むべき技術書」を挙げた記事から、薦められている本を拾う**(Qiita の公式 API。キー不要)。
  記事に貼られた Amazon リンクの ASIN は書籍なら ISBN-10 そのものなので、ISBN-13 に直して
  openBD で書誌を引く(チェックディジットを検算するので `B0…` の Kindle 専売は落ちる)。
  **保存するのは ISBN と出典記事の URL だけ**で、記事の本文は保存しない。
  何本の記事で薦められたかが「推薦回数」で、**レビュー(読まれた量)とは別軸の指標**
- 「書籍」画面は**トピックごとの折りたたみ**。トピック名を押すと開き、複数のトピックで
  見つかった本はそのすべてに出る。先頭に「記事で薦められている本」の枠(**推薦 2 本以上**)が
  あり、並びは推薦回数 → 読まれている度合いの順。トピックの中でも推薦のある本は強調される
- `Books:MinReviewCount` を上げると、レビューがそれ未満の本は保存しない(既定 0 = 足切り無し)。
  **レビューが取れた本だけが対象**で、取れていない本は落とさない —— 楽天のアプリ ID が
  無い環境で 1 冊も保存されなくなるのを避けるため

現状の制限:

- 一度保存した本の書誌情報は**更新しない**(レビュー件数だけは次に見つけたときに更新する)
- Google Books の `q=` はタイトル以外(著者・説明文)にも当たるため、**キーワードと関係の薄い本が
  混じる**。イベント側の `KeywordMatcher` のような絞り込みは書籍には入れていない

## 本番運用

docker compose で動かす。ホストに .NET も Postgres も要らない。

```bash
cp .env.example .env   # 使う外部 API のキーを入れる
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

`http://<ホスト>:7020` で開く(`.env` の `PORT` で変更可)。データはリポジトリ直下の
`data/`(Postgres は `data/postgres`、Data Protection の鍵は `data/keys`)に入る ——
**バックアップはこのディレクトリを丸ごとコピーするだけでよい**。未適用のマイグレーションは
起動時に自動で当たるため、更新は `git pull` して同じコマンドを打つだけでよい。

- イメージは main への push で GitHub Actions がビルドし、GHCR へ公開する
  ([.github/workflows/build-and-push-image.yml](.github/workflows/build-and-push-image.yml))。
  タグは `latest` とコミット識別用の `sha-xxxxxxx`。デプロイ先はビルドせず
  `docker compose pull && docker compose up -d` でよい
- 非公開リポジトリなので GHCR のパッケージも非公開。pull 側では事前に
  `read:packages` 権限の PAT で `docker login ghcr.io` が必要
- 障害時は `.env` の `TECH_ANTENNA_IMAGE` に `ghcr.io/rtcode337/tech-antenna:sha-xxxxxxx` を
  指定すれば任意の時点のイメージに戻せる
- リポジトリを置けない環境(NAS のコンテナマネージャー等、管理画面に YAML を貼り付ける
  タイプ)向けには [docker-compose.standalone.example.yml](docker-compose.standalone.example.yml) を
  用意している。実値を直書きするので、`.env` と同じくコピーした側(`docker-compose.standalone.yml`)は
  コミットしない
- TLS は前段のリバースプロキシで終端する前提(コンテナは HTTP のみ待ち受ける)。
  プロキシ配下に置くときは `.env` で `FORWARDED_HEADERS_ENABLED=true`
- **収集と要約は既定では自動実行しない**(画面のボタンを押したときだけ動く)。
  外部 API や LLM の無料枠を意図せず使い切らないため。定期実行にするときは `.env` で
  `COLLECTION_AUTORUN` / `BOOKS_AUTORUN` / `SUMMARY_AUTORUN` を `true` にする

## 開発環境

.NET 10 SDK が要る(Ubuntu 26.04 なら `sudo apt install -y dotnet-sdk-10.0`)。

```bash
dotnet build
dotnet test
dotnet run --project src/TechAntenna.Web   # http://localhost:7020

# 画面を触るときはホットリロード付きで(保存すると再起動なしでブラウザに反映される)
dotnet watch --project src/TechAntenna.Web --launch-profile watch   # http://localhost:7022
                                                                   # (0.0.0.0 で待つので他の端末からも見える)
```

DB は PostgreSQL。接続文字列 `ConnectionStrings:Default` を設定して起動すると
未適用のマイグレーションが自動で適用される。未設定の場合はメモリ上のストアで動く
(再起動すると消える)。

収集は画面のボタンから実行する(→[トピックの再編成](#トピックの再編成))。記事はトピックを
選んでいなくても集まるが、イベントと書籍は選択が空だと 1 件も集まらない。

開発サーバーから compose の DB の実データを読むときは、`docker-compose.dev.yml` を
重ねて 7021 を開ける(`127.0.0.1` のみ。本番では重ねない)。

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
set -a; . ./.env; set +a
ConnectionStrings__Default="Host=localhost;Port=${POSTGRES_PORT:-7021};Database=${POSTGRES_DB:-techantenna};Username=${POSTGRES_USER:-techantenna};Password=${POSTGRES_PASSWORD:-techantenna}" \
  dotnet run --project src/TechAntenna.Web
```

**本番コンテナと同じ DB を見ることになる**ので、開発中のマイグレーションを流したくない
ときは重ねないこと(起動時に自動適用される)。SQL で覗くだけなら開ける必要はない
—— `docker compose exec db psql -U techantenna -d techantenna`。
